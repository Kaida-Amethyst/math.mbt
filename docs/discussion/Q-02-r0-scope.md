## 建议的解决方案

### A1. 采用完整的“可靠性基线”工作包 【已采纳】

#### 方案描述

R0 包含以下内容：

1. 为 `ulp_error`、`roundeven`、`clamp`、`norm`、`logsumexp`、`nextafter` 和 `pown` 明确最小契约。
2. 将已经确认的反例写成永久回归测试。
3. 先修复并独立验证 ULP 测量器，再修复其余基础函数。
4. 在所有支持后端运行 debug/release 回归测试。
5. 移除失效的 `macos-13` CI 项，使默认分支恢复绿色。
6. 清点公共 API 的成熟度，但不在 R0 中认证全部函数。

#### 优点

- 同时修复错误的“尺子”、已知基础缺陷和失真的 CI 外部信号。
- 范围仍限定在已经有事实依据的问题，没有扩张到特殊函数认证。
- 完成结果可以直接观察和验证。

#### 缺点

- 包含代码、测试、文档和 CI 多种修改，需要控制提交边界。
- 其中若干函数的边界契约仍需先完成后续问题的决策。

## 最终采用方案

A1. 采用完整的“可靠性基线”工作包
