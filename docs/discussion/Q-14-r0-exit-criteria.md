## 建议的解决方案

### A1. 以已知缺陷、测试尺子、全后端和绿色 CI 四类门槛验收 【已采纳】

#### 方案描述

R0 完成需要同时满足：

1. 所有已确认最小反例都有永久测试，并在修复后通过。
2. ULP 测量器有独立、可审阅的正确性测试，不再发生负距离或静默通过。
3. R0 范围内的测试在所有支持后端以及 debug/release 模式通过，并满足已决定的一致性标准。
4. 默认分支 CI 为绿色，失效的 `macos-13` 项已清理。
5. 公共 API 成熟度清单已生成，且没有把缺乏证据的函数默认为 stable。

#### 优点

- 每项门槛都能客观检查。
- 同时覆盖代码正确性、测试可信度和仓库外部信号。
- 不要求 R0 提前完成大规模特殊函数认证。

#### 缺点

- “独立、可审阅”仍需要通过具体测试案例进一步落实。
- 门槛依赖多个契约问题，实施时必须把已经采用的结论同步落实为验收项。

## 最终采用方案

A1. 以已知缺陷、测试尺子、全后端和绿色 CI 四类门槛验收
