# Q-08. norm 对空向量的处理 〔已解决〕

> 最后更新日期：2026-08-12
> 仓库：Kaida-Amethyst/math.mbt
> 记录者：Codex

## 问题描述

`norm` 接受任意数组，但当前文档没有定义空数组的结果。R0 需要决定空向量是返回加法单位元 `0.0`，还是被视为非法输入。这个决定不依赖 NaN 与无穷的优先级。

## 问题引发模型

### 问题复现

当前缩放算法从空数组得到最大值 `0.0`；由于循环体不执行，最后计算 `0.0 * sqrt(0.0)`，实际返回 `+0.0`。但这一行为没有写入契约，也没有测试保护，仍可能在重构时意外改变。它与非空全零向量不同：后者会进入循环并产生 `0.0 / 0.0`，属于另一个实现缺陷，不由本问题决定。

### 外部契约比较

- [ECMAScript `Math.hypot`](https://tc39.es/ecma262/2025/multipage/numbers-and-dates.html#sec-math.hypot) 接受零个或多个参数，并明确在零参数时返回 `+0`。
- CPython 的任意维 `math.hypot` [明确测试 `hypot() == 0.0`](https://github.com/python/cpython/blob/v3.14.0/Lib/test/test_math.py#L806-L829)。
- NumPy `linalg.vector_norm` 委托给二范数实现；空数组的点积或平方和归约为零，因而[返回 `sqrt(0)`](https://github.com/numpy/numpy/blob/v2.5.0/numpy/linalg/_linalg.py#L2746-L2803)。

这几项外部参照在空输入上没有出现与 `0.0` 相竞争的主流结果。

## 建议的解决方案

### A1. 空向量返回正零 【已采纳】

#### 方案描述

定义 `norm([]) -> +0.0`，并对结果的零符号添加测试。

#### 优点

- 同时对齐 ECMAScript `Math.hypot`、CPython `math.hypot` 和 NumPy 二范数。
- 保留范数作为平方和归约的单位元语义，也使空向量与全零向量自然一致。
- 调用签名无需增加错误通道。

#### 缺点

- 当前由 `1.0 / norm(vec)` 定义的 `rnorm([])` 会相应得到正无穷；该下游行为需要在公共 API 清点时单独核对。

### A2. 把空向量视为非法输入并 panic 【不建议】

#### 方案描述

要求输入至少含一个坐标，空数组立即 panic。

#### 优点

- 如果调用者业务上不允许零维向量，可以尽早暴露输入错误。

#### 缺点

- 与上述三个直接参照都不一致。
- 把业务层的非空约束放入通用数学归约，削弱组合性。

## 最终采用方案

A1. 空向量返回正零
