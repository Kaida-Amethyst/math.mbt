# Q-03. ULP 距离的语义契约 〔已解决〕

> 最后更新日期：2026-08-12
> 仓库：Kaida-Amethyst/math.mbt
> 记录者：Codex

## 问题描述

当前 Double 版本的 `ulp_error` 直接对有符号 IEEE 754 位模式做减法，跨符号位时可能溢出；`ulp_error(-0.0, 0.0)` 已复现为负数。由于现有精度断言依赖这个结果，需要先定义有限值、signed zero、NaN 和无穷之间的距离语义。

## 问题引发模型

### 问题复现

调用 `ulp_error(-0.0, 0.0)`，当前实现返回 `-9223372036854775808`，而不是表示相等的 `0`。`assert_ulp` 只检查距离是否大于阈值，因此负溢出还能静默通过。

### 最小复现例子

触发条件是直接把正负浮点数的有符号位模式相减。若先把位模式映射为保持浮点数序关系的整数编码，再计算有界距离，符号位不再直接引发该溢出。

### 问题分析

这个函数既是公共 API，又承担测试基础设施角色。它需要分别定义普通有限值、跨零有限值、`+0/-0`、相同或不同无穷、NaN 与非 NaN 的结果，并保证返回类型不会把过大距离变成负数。

## 建议的解决方案

### A1. 保留现有特殊值意图并改用有序编码计算距离 【已采纳】

#### 方案描述

将 `+0` 和 `-0` 视为距离 0；相同方向的无穷之间距离为 0；双方都是 NaN 时距离为 0；特殊值不匹配时返回可表示的最大哨兵值。普通有限值先转换为保持数值顺序的整数编码，再计算不会变成负数的距离。Float 和 Double 使用同一套语义。

#### 优点

- 修复已确认的跨符号位溢出，同时最大程度保持当前注释表达的意图。
- Float 与 Double 的测试含义一致。
- 现有 ULP 断言可以继续使用统一接口。

#### 缺点

- “两个 NaN 的距离为 0”是测试便利语义，不是通常意义上的数值距离。
- 超大有限距离无法精确保留，按 Q-16 的决定饱和为最大哨兵值。

## 最终采用方案

A1. 保留现有特殊值意图并改用有序编码计算距离
