# Q-11. 稳定 API 的跨后端一致性标准 〔已解决〕

> 最后更新日期：2026-08-12

## 问题描述

库同时支持 wasm、wasm-gc、JavaScript 和 native。R0 的测试门槛需要明确：稳定 API 是否必须在所有后端逐位相同，还是只要求遵守相同的特殊值契约和误差上界。

## 建议的解决方案

### A1. 要求语义和误差界一致，逐位差异需记录 【已采纳】

#### 方案描述

所有支持后端必须满足相同的特殊值、定义域和误差上界契约；只有被明确证明必要的尾数差异可以存在，并需要测试和文档记录。

#### 优点

- 符合不同代码生成后端可能采用不同底层指令的现实。
- 仍然给用户提供统一、可测试的行为保证。

#### 缺点

- 不能保证跨后端结果逐位可重现。
- 需要维护误差界以及允许差异清单。

### A2. 所有稳定 API 在所有后端逐位一致

#### 方案描述

只要 API 标记为 stable，其所有被支持输入在四个后端都必须返回相同位模式。

#### 优点

- 跨后端重现性最强，判断门槛直观。

#### 缺点

- 对依赖目标指令或运行时数学实现的函数可能代价极高，甚至无法实现。
- 可能迫使所有后端使用较慢的统一软件实现。

## 最终采用方案

A1. 要求语义和误差界一致，逐位差异需记录
