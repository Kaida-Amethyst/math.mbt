# Q-21. 外部 oracle 与纯 MoonBit 发布边界 〔已解决〕

> 最后更新日期：2026-08-12
> 仓库：Kaida-Amethyst/math.mbt
> 记录者：Codex

## 问题描述

讨论已经明确一个约束：开发和认证阶段可以临时借助 Python、C FFI、高精度库或其他外部能力，但最终发布的库必须是纯 MoonBit。本问题把“纯 MoonBit”落实为可检查的仓库与测试边界，并确定外部 oracle 如何留下可重复的证据，而不成为用户构建或常规测试的运行时依赖。

## 建议的解决方案

### A1. 外部工具离线生成证据，发布测试只消费固化数据 【已采纳】

#### 方案描述

把 Python、MPFR、Arb 或 C FFI 工具隔离在 `tools/oracle/`，禁止 `src/` 中的任何包导入或调用它们。外部工具只在显式的认证或数据再生成步骤中运行，生成由纯 MoonBit 测试读取的固定 IEEE 754 位模式案例；生成器同时记录 oracle 名称与版本、精度、舍入模式、随机种子和数据格式，使结果可以复核。

语义裁判与数值 oracle 分工：IEEE 754/C23 和成熟库的公开契约用于确定特殊值及定义域行为，高精度库用于生成有限数值参考。Python 可以负责调度和格式转换，但其默认浮点或宿主 `libm` 不自动被视为高精度真值。若使用 C FFI，应限制在单独的 native 验证工具或仅认证阶段启用的包中；MoonBit 支持的 FFI 与目标条件见官方 [FFI 文档](https://docs.moonbitlang.com/en/latest/language/ffi.html) 和 [包目标配置](https://docs.moonbitlang.com/en/latest/toolchain/moon/package.html#supported-targets)。

“可发布”至少满足：发布源码和常规测试没有 Python、C 运行库、外部 `libm`、MPFR、网络或子进程依赖；只安装 MoonBit 工具链的干净环境可以构建并运行全部发布测试；外部 oracle 不在标准构建和测试命令中隐式执行。外部工具及其生成数据可以留在仓库中用于再认证，但不进入库的运行时依赖。

外部差分搜索输出的失败案例必须缩减并固化为 MoonBit 回归测试。这样即使发布环境不运行 oracle，已经获得的证据仍随仓库保留。

#### 优点

- 开发阶段可以利用成熟高精度生态，同时保持发布产物和常规测试纯 MoonBit。
- 固化位模式避免文本浮点转换和宿主环境差异，使多后端测试可重复。
- oracle 元数据和生成器留在仓库中，参考结果可以重新生成和审查。
- 外部搜索发现的价值不会随着工具退出发布流程而丢失。

#### 缺点

- 固化语料需要在 oracle 或生成规则变化时显式再生成并审查差异。
- 仓库仍需维护额外语言和工具链，只是它们不属于发布依赖。
- 离线数据只能覆盖选定样本，仍需性质测试和持续差分搜索补充。

## 最终采用方案

A1. 外部工具离线生成证据，发布测试只消费固化数据
