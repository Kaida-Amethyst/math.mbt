# Q-05. clamp 对 NaN 参数的处理 〔已解决〕

> 最后更新日期：2026-08-12
> 仓库：Kaida-Amethyst/math.mbt
> 记录者：Codex

## 问题描述

`clamp` 的当前文档声明 `x`、`min`、`max` 中任一参数为 NaN 时结果为 NaN，但实现只依赖普通比较，因此 NaN 位于边界参数时可能返回有限值。R0 需要决定是否把文档中的传播规则固定为稳定契约。

## 问题引发模型

### 问题复现

`clamp(2.0, NaN, 1.0)` 当前返回 `1.0`，没有传播 NaN。

### 问题分析

NaN 比较均为 false，而当前实现没有显式检查三个参数。保留文档规则需要在边界交换和范围比较之前处理 NaN。

## 关联问题

1. [Q-01. 稳定 API 的语义裁判顺序](Q-01-semantic-precedence.md)（依赖：参考标准和 MoonBit Core 行为用于核对最终契约）
2. [Q-06. clamp 对倒置边界的处理](Q-06-clamp-inverted-bounds.md)（一般关系：两个规则共同组成 clamp 的边界契约，但可独立决定）

## 建议的解决方案

### A1. 保留文档约定，任一参数为 NaN 时返回 NaN 【已采纳】

#### 方案描述

将当前文档承诺变成显式实现和黑盒测试，无论 NaN 出现在输入值还是任一边界，都返回 NaN。

#### 优点

- 修复实现与文档不一致。
- 规则简单、对三个参数对称。

#### 缺点

- 如果 MoonBit Core 使用不同的 NaN 规则，需要公开记录差异。

## 最终采用方案

A1. 保留文档约定，任一参数为 NaN 时返回 NaN
