## 建议的解决方案

### A1. 独立实现内部 ULP 距离并以白盒矩阵验收 【已采纳】

#### 方案描述

本次改造按下列边界实施：

1. 将 `ulp_error`、`ulp_error_f32`、`assert_ulp` 和 `assert_float_ulp` 从通用 `utils.mbt` 移入独立的 `ulp_distance.mbt`。保留现有名称和返回类型，使仓库内现有数值测试无需同步改写调用方式。
2. 移除 `ulp_error` 和 `ulp_error_f32` 的 `pub` 可见性；两个断言辅助函数继续保持私有。重新生成包接口后，公共接口中不得再出现两个 ULP 测量函数。
3. Double 与 Float 采用同一算法结构：先处理特殊值，再将有限值位模式转换为保持数值顺序的无符号编码，在无符号域中由较大编码减去较小编码，最后才转换为现有的有符号返回类型。
4. 特殊值规则固定为：`+0.0` 与 `-0.0` 距离为零；双方都是 NaN 时距离为零；相同方向的无穷距离为零；其余包含 NaN 或无穷的不匹配组合返回最大哨兵值。
5. 有限距离超过 `Int64` 或 `Int` 的最大正数时，在转换返回类型之前饱和为相应最大哨兵值。实现不得通过可能溢出的有符号减法或对最小有符号整数取绝对值来计算距离。
6. 删除改造后不再使用的 `abs_i64` 等旧辅助逻辑，避免错误算法继续留在通用工具中。
7. 新增 `ulp_distance_wbtest.mbt`，从包内视角直接验证私有距离函数。测试输入的相邻关系通过显式 IEEE 754 位模式构造，不依赖尚待修复的 `nextafter`。

白盒测试至少覆盖以下矩阵：

- 相同有限值和普通相邻正数、负数；
- `+0.0` 与 `-0.0`；
- `-最小次正规数`、零和 `+最小次正规数` 的跨零距离；
- 普通跨符号有限值及参数交换后的对称性；
- 最大负有限值到最大正有限值的饱和；
- NaN、正无穷和负无穷的相同组合与不匹配组合；
- Double 与 Float 的相同契约；
- 所有返回结果非负，且交换两个参数不改变结果。

改造完成后依次运行 `moon fmt`、`moon check --deny-warn`、所有支持后端的 debug/release 测试和 `moon info`。验收时同时审查生成接口差异，确认只发生预期的两个公共 ULP 函数收回；成熟度清单和其他基础函数修复留给后续工作。

#### 优点

- 先修复后续精度验证依赖的测量基础，避免错误尺子继续制造静默通过。
- 实现、断言和白盒测试集中在同一职责边界，通用工具文件不再混入测试策略。
- 保留内部函数名称和返回类型，把现有数值测试的连带改动降到最低。
- 测试不依赖 `nextafter` 或被测算法本身，证据链相对独立。

#### 缺点

- 收回两个已发布的公共函数属于接口变更，仍需在将来的版本说明中明确记录。
- 最大哨兵同时代表特殊值不匹配和超大有限距离，内部调用者不能区分两者。
- 现有内联数值测试仍依赖同一组内部断言辅助函数；本次只验证尺子，不重新组织全部历史测试。
