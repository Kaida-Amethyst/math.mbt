# Q-16. ULP 距离超过返回范围时的表示 〔已解决〕

> 最后更新日期：2026-08-12
> 仓库：Kaida-Amethyst/math.mbt
> 记录者：Codex

## 问题描述

Q-03 已决定使用保持浮点数序关系的整数编码计算 ULP 距离，但两个有限 Double 之间的完整距离可能超过当前 `Int64` 正数范围。本问题只决定这种超大距离如何表示，不重新讨论 NaN、无穷或 signed zero 的语义。

## 问题引发模型

### 最小边界例子

`Int64` 最大正数是 `9_223_372_036_854_775_807`。按 Q-03 的有序编码并把 `-0.0` 与 `+0.0` 合并为同一点后，`-@double.max_value` 到 `@double.max_value` 的精确距离是 `18_437_736_874_454_810_622`，约为前者的两倍。两端都是有限数，但结果无法装入 `Int64`。

### 问题分析

如果仍用 `Int64` 做差或取绝对值，这类合法有限输入可能溢出并重新变成负数，复现 Q-03 正要消除的“错误距离让断言静默通过”问题。因此必须在计算前决定：超出范围时饱和，还是改用能容纳完整距离的表示。通常 ULP 断言只关心距离是否超过很小的阈值，所以饱和不会改变断言结论；但它不再是精确测量值。

## 建议的解决方案

### A1. 超出范围时饱和为最大哨兵值 【已采纳】

#### 方案描述

保留当前返回类型；只要实际距离超出可表示正数范围，就返回最大哨兵值，保证结果永不为负。

#### 优点

- 对现有断言用途足够，因为超大距离一定超过正常 ULP 阈值。
- 修改范围较小。

#### 缺点

- 丢失超大距离的精确值。
- 最大哨兵同时用于特殊值不匹配时，调用者无法区分原因。

### A2. 改变返回表示以容纳完整有限距离

#### 方案描述

调整返回类型或结果结构，使任意两个有限浮点数之间的完整 ULP 距离都能精确表示，并另外表达特殊值不匹配。

#### 优点

- 距离含义完整，不需要饱和。
- 可以把有限距离和特殊值状态明确区分。

#### 缺点

- 接口和断言辅助函数都更复杂。
- 若 Q-04 决定继续公开，会形成更明显的公共 API 变更。

## 最终采用方案

A1. 超出范围时饱和为最大哨兵值
